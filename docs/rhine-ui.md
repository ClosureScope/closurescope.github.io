# RhineLabUI 博客界面

首页移植自 [LBEILC/RhineLabUI](https://github.com/LBEILC/RhineLabUI)，保留三维阵列、玻璃文档抽取、解密、检索与声音设置。访问网站后直接进入文章选择界面；开屏动画、进入确认、重播入口及开场动效选项已删除。模型加载期间只显示简短状态提示，声音在首次正常点击或按键时按浏览器策略解锁，不阻挡文章浏览。上游源码在 `site/src/rhine/`，资源在 `site/public/rhine/`，原项目 MIT 许可证、字体与声音来源说明一同保留。首阶段不接入上游 PWA 与壁纸宿主功能。

界面文案统一使用「文章」，后续新增提示、按钮和说明也遵循这一用词。

## 写文章

继续在 `posts/<分类>/*.typ` 写文章。新增、删除文件或分类后，`pnpm dev` 会重新编译并刷新；`pnpm build` 会重新扫描并生成发布版本。线上页面在重新构建部署后更新。

- 有文章的分类文件夹对应一个栏目；分类下直属 `.typ` 对应一篇文章。
- 分类和文章按现有构建脚本的文件夹名、文件名顺序排列。
- 分类数量和每类文章数量独立计算，没有五类、每类八篇的限制；空分类不显示。
- 左右切换分类，上下切换文章，首尾循环；每类记住本次选中的文章。
- 三维画面按视口复用模型，重复出现的模型属于循环展示；栏目计数显示真实数量。
- 收藏入口、收藏按钮、收藏快捷键和存储逻辑已删除。文章使用文件名 `slug` 定位，不再生成或展示文件编号；选择区、悬停提示、三维标签、详情和搜索结果均使用文章标题。
- 进入文章后，文件模型在原有三维场景中抽出、转正，原版场景中的阅读区域居中、放大，直接显示文章标题和正文，不再保留单独的左侧模型栏或白色卡片；侧边保留返回箭头，顶部保留原有 DIRECTORY 入口，不再显示独立阅读。文章信息、访问日志、格式元数据与模型查看入口已移除。原有 `/posts/<slug>/` 文章地址仍可直接访问。
- 顶部品牌和导航沿用原仓库的左右定位，上边距减半；小屏保留安全区间距；左上角显示 ClosureScope；选择区直接以文章标题作为可点击的主标题，长标题自然换行。选择区的数据库、编号、权限标签和页脚授权、Powered By 字样已移除。

设置面板仅保留音乐、音效（含各自音量）和全屏（FULLSCREEN / 全屏）。画质入口已移除，博客固定使用原始预设，不读取旧画质或超级性能设置；保留 Wallpaper Engine 自身的属性接口。

## 正文渲染隔离

现有 Typst 编译、`global.css`、网页字体和数学 SVG 处理保持不变。正文通过同源 iframe 载入现有文章页面，与三维界面的 CSS 隔离。内嵌阅读隐藏重复的站点页眉和返回链接，并将页面背景设为透明以衔接原版场景，保留原有文章标题、正文容器、样式和公式标记；独立文章页面保持原样。

阅读区域放在未缩放的浏览器坐标层，水平居中，最大宽度 1240px，滚动视口上边界与 ClosureScope 品牌元素的上沿对齐，并延伸至屏幕底部；初始标题位置保持不变，滚动时正文在品牌上沿处裁切消失，返回按钮仅显示左箭头，与栏目切换按钮共用 46px 按钮及 24px 箭头样式；放在正文左侧的留白中，不占用顶部阅读高度；小屏为箭头保留侧边距。完整三维场景统一轻度虚化并叠加半透明米色薄雾，正文区域没有独立磨砂边界，顶部品牌、导航和文字保持清晰，保留分隔线，不增加不透明卡片、边框、阴影或重复品牌栏；模型恢复原版的镜头构图。阅读窗口沿用最初博客的正文大小：桌面 17px、小屏 16px，桌面内嵌正文行宽从 41.23em 加宽至 54em（17px 下约 918px），小屏正文宽度随侧边按钮留白自适应，字体映射、SVG 大小与基线、公式滚动均保留，独立文章与 PDF 不变；不会随着三维舞台缩放；模型和扫描线始终位于正文下层；阅读中的模型固定，不能拖动旋转，镜头不再随指针偏移；进入文章的抽出与镜头响应加快，交互解密速度从 1.5 倍提升至 3.5 倍（参考动画时序不变）；默认先完整播放抽出、转正和解密动画，期间保持场景清晰且正文不显示，结束后全场景虚化、正文与返回按钮一起淡入，返回时背景恢复清晰、模型归位。仅隐藏文章窗口的纵向滚动条，正文仍可用滚轮、触摸与键盘滚动，公式和代码内部的横向滚动不变。侧边返回按钮与正文中的 Escape 返回文章选择，DIRECTORY 与 `/` 打开文章目录。

首页只接收 `slug`、标题、分类，不把全部文章 HTML 打入三维界面 JavaScript。正文仍是可独立访问的静态 HTML。

## 移动设备渲染开销评估

原始预设使用 100% 渲染比例、最高 1.5 倍像素密度、2048² 阴影、32 样本环境遮蔽、景深和全分辨率玻璃透射；总像素上限 829 万仅用于限制极端尺寸，不能代替移动设备性能适配。

以下为调用 `renderDimensions` 得到的渲染分辨率计算，不是真机帧率测试：

| 示例视口 | 设备像素比 | 实际渲染尺寸 | 每帧像素 |
| --- | --- | --- | --- |
| 手机 390 × 844 | 3 | 585 × 1266 | 约 74 万 |
| 平板 1024 × 1366 | 2 | 1536 × 2049 | 约 315 万 |

平板示例每个全屏渲染过程的像素数约为手机的 4.25 倍，并不等同于帧率降低 4.25 倍。阴影、多次后处理和透明玻璃材质使原始预设仍有明显 GPU 开销；Three.js 的 [MeshPhysicalMaterial 文档](https://threejs.org/docs/pages/MeshPhysicalMaterial.html) 也说明其每像素成本高于普通材质。中低端或较旧设备存在掉帧、发热和耗电风险，不能根据桌面无头浏览器测试保证移动端流畅。

已有保护包括像素密度限制、阴影和未变化画面的复用、页面进入后台后暂停场景更新。后续如需优化，优先考虑移动端降低后处理与阅读期间减少背景渲染，保持正文文字与数学 SVG 完全不受影响。本次按要求固定原始预设，没有另行加入自动降画质策略。

## 维护和验证

- `scripts/archive-index.mjs`：从现有文章元数据建立栏目、文章和位置索引。
- `site/src/rhine/data.ts`、`archive-loop.ts`：内容映射与循环；渲染池大小与文章身份分离。
- `scene.ts`：保留上游渲染，坐标重置支持任意列数及不同列长。
- `blog-reader.ts`、`blog.css`：阅读区域定位与界面适配，调整内嵌文档透明背景、阅读宽度和留白，保留原有文字与公式样式。
- `scripts/patch-rhine-rolling-number.mjs`：沿用上游对固定版本滚动文字依赖的测量修正；开发与构建前自动执行。

```bash
pnpm test:archive
pnpm build
pnpm test:math
pnpm test:archive-ui
```

`test:archive` 覆盖不同列长、七列、单篇栏目、四十篇栏目、反向循环、长期滚动坐标重置及旧版动效设置迁移。`test:archive-ui` 使用生产构建检查桌面与手机直接进入文章选择界面、旧设置兼容、精简设置和文章导航、搜索筛选、场景内阅读尺寸与模型抽取状态、末尾滚动、内嵌与独立页面正文及字体一致性；另以真实场景更新（仅跳过 GPU 栅格化）检查加速后的模型抬升、镜头移动、解密、禁止旋转和归位。测试不启动或停止开发服务器。数学回归测试仍使用原有测试。
